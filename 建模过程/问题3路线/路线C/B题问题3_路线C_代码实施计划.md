## 1. 当前代码能复用什么，还缺什么

| 当前实际情况 | 对路线C的影响 | 计划中的处理 |
|---|---|---|
| LocalSimulator已有移动、检测、清除和虚拟计时 | 可以作为二维仿真底座 | 核验边界、失败语义与计时，增加可审计事件 |
| FixedErrorField.value忽略位置，每频道一个常量 | 旧实验未覆盖空间变化误差 | 保留常量对照，增加固定空间误差场 |
| ChannelTrack只有观测、七点记录、位置与距离上界 | 没有原方案要求的中心、面积和真正外包域 | 实现geometry与搜索图，再生成757维输入 |
| 执行逻辑在ActiveRouteBPolicy._execute | C直接调用会把规则策略与环境耦合 | 提取公共EpisodeSession |
| 4个SCAN都在同一个预定覆盖点，只分频道组 | 网络没有真正选择搜索地点的余地 | 候选v2提供不同覆盖点；B/C一起采用 |
| 局部候选只取最小频道号的前4个 | 高频道号可能长时间没有选择机会 | 记录等待时长，稳定轮转 |
| choose有TRACKING就选最近局部候选 | 是每步局部优先，并没有保存一个锁定频道 | 区分普通选择与强制兜底，不把它误述为已经实现的频道锁定 |
| 清除常在LOCALIZE内部直接执行 | CLEAR槽位未充分发挥作用，估价可能漏掉自动清除 | 公共执行语义固定，实际奖励计全部耗时 |
| run到500步直接返回belief | 无法区分成功、截断和故障 | 增加明确终止原因及任务完成证据 |
| experiment以清除计数和真值数量相等判断成功 | 没核对清除频道集合、公开结束证据和异常 | 新评估器分别核对真值全清与证据完成 |

之前500场景结果是特定版本、特定生成器下的实测，不等于全部误差环境或所有输入下的保证。新公共层或候选集会改变行为，必须重新跑B，不能直接与旧CSV做因果比较。

## Step C0：保存B参考版本并修好执行契约

先保存当前B及其依赖源文件、配置和文件哈希到唯一编号的基线快照目录，旧实验原样保留；不删除或覆盖用户文件。选20个现有开发场景保留逐事件轨迹作回归对照。此阶段只提取执行器时应逐事件、逐项时间一致；后续修正规则时另记行为变更，不能强行让错误结果一致。

公共数据定义：`PublicSnapshot`含机器人位置/当前频道/虚拟时间/实际预算比例/20频道摘要/停滞及等待记录；`StepResult`含动作ID、按顺序发生的事件、时间增量、首次发现数、成功清除数、完成标志和原因。它们不含目标真值。

核心接口约定：

```text
EpisodeSession(backend, rules, task_config)
session.snapshot() -> PublicSnapshot
session.build_candidates() -> tuple[Candidate, ...]  # 固定12槽
session.execute(action: ActionSpec) -> StepResult
session.completion_reason() -> str | None
session.report() -> EpisodeReport
```

动作执行前完整验证坐标、频道、候选版本、几何证据，失败输入不先移动再报错。模拟器成功清除物理边界严格为距离≤20 m；数值裕量应使规划更保守，不能把物理成功范围扩大到20 m之外。

目前模拟器假设清除自动换频、失败也收取5 s；附件协议未确认前，把它们放入带名称的本地假设计费配置并随结果导出，不当成官方规则事实。真实计时等接官方后核对。新策略通过证据避免试探性失败清除。

七点证据核对覆盖ID与实际测量位置，不接受任意7个编号；已清除频道不能被后续误观测改回TRACKING。任务完成必须有公开证据；正式任务清除不足10个却全部排除时记一致性异常。单目标测试用显式诊断任务配置，不能修改正式题目数量规则。

验收：正常动作账本一致；非法频道不改变位置时间；20 m外清除失败；少于10个的异常不算正常完成；开发动作上限、通信错误和任务完成均有不同reason。B通过新会话执行一次完整任务后，才进入C1。

## Step C1：真正的可行域与空间误差仿真

新增geometry：复用第一问半平面表示，累积阳性±1°角约束、目标1800 m圆和接收1500 m圆，所有圆使用外包近似。旧几何算法仅作适配参考，不原样调用最昂贵的边界全组合求解。首版使用凸外包域；阴性约束记录到搜索图，不强行给凸域挖孔。

```text
initial_region(rules) -> Region
update_region(region, observation, rules) -> Region
region_summary(region) -> RegionSummary(center, cover_radius, area, valid)
SearchGrid.observe_none(channel, point) -> None
SearchGrid.gain(point, channels) -> float
```

RegionSummary的center为实际采用的覆盖中心；半径由所有外包顶点到中心的最大距离计算，包含点/线段退化；空集为异常。需要时精修最小覆盖圆。阴性搜索网格只用于收益排序，中心采样删格不构成ABSENT或清除证据。

半距离收缩产生的距离球作为新增公开几何证据保留，明确它对应哪个锚点。更新上界须在对应移动成功后提交；切换目标或返回旧测点时不能把旧位置的距离界错配到新位置。几何与距离球任一提供可靠20 m证据即可清除。

误差场新增固定网格节点和双线性插值。节点值始终在[-1°,1°]，同局固定，同点查询一致；越界位置有确定扩展规则，不按检测次数重抽。目标数、频道、布局、接收半径和误差场使用独立派生种子。保留旧常量场；新增50/200/500 m节点间距、常量±1°及组合压力场景，均注明是本地假设。

验收：跨零角度、圆边界、退化区域和矛盾观察可诊断；固定目标在每次合法更新后仍落入外包域；同点误差一致且界内；不同位置误差允许变化；最小半径＋边缘布局＋变化误差可组合运行。此阶段测试侧可以读真值检查几何，编码器仍不能读。

## Step C2：让候选集包含值得学习的选择

保留12槽接口：4扫描、4定位、3清除、1兜底。扫描候选从不同未完成覆盖点选出，首版不增加任意连续坐标输出。若机器人当前位于有效覆盖点且该处仍有待查频道，优先保留该点；其余按预计成本与频道级新增覆盖收益选取。每个扫描动作明确有序频道列表：当前频道优先，其余按稳定规则。候选中提供同点全待查频道与分组扫描的版本时，须记录为独立候选配置实验，不能训练后悄悄改变。

局部候选来自实际可行域及收缩策略，按等待时长和稳定频道顺序轮转，保留可推进的候选。下一次收缩移动已能保证20 m时可直接形成CLEAR候选，避免强行再花5 s检测。全体候选按kind、位置、频道与语义去重，action_id包含完整频道列表；空槽补零，不调用空动作估时。

安全规则独立于B人工偏好：正常模式允许扫描/定位/清除之间选择；NEAR立即处理；长期停滞进入确定兜底。兜底槽既能提供未完成覆盖扫描，也能提供待定位目标推进。进入强制兜底后保留任务游标/锁定频道，掩码只开放对应动作，直到指定子任务完成或失败。触发阈值按公开进展与虚拟耗时配置、验证前冻结。

B可以保留“优先局部”的选择偏好，C可以学习其他顺序；但两者必须使用同一合法集合、执行器和安全接管条件。不能先采样A，再由B改成B动作，仍用A概率更新PPO。

验收：同一公开状态候选完全一致；候选缓存与索引一致；非结束状态至少有一个合法且能推进的候选；清除不读取真值；高编号目标不会永久出不了候选；存在不同搜索点选择；记录有效槽位数及强制单选比例。新候选B重跑开发验证集，建立新的公平对照。

## Step C3：完成757维观测和Gymnasium环境

```text
encode_observation(snapshot, candidates, schema) -> float32[757]
RouteCEnv.reset(seed=None, options=None) -> (obs, info)
RouteCEnv.step(action_index) -> (obs, reward, terminated, truncated, info)
RouteCEnv.action_masks() -> bool[12]
```

757维对应原方案：全局25＋20频道×18＋12候选×31。频道包含真实计算的覆盖中心/覆盖半径/外包面积/未排除比例，不拿最后检测点冒充目标中心，也不把缺少字段用随意数值填满后宣称完成原方案。UNKNOWN位置填0且有估计位为0；掩码与候选有效位一致。每个字段的单位、尺度、缺失值和顺序保存为schema.json。

一轮step：校验缓存动作→公共会话执行→收集全部事件和时间差→算奖励→判断完成/失败→生成并缓存下一观测候选。NEAR清除作为当前宏动作结果的一部分记账；若扫描被中断，只保留实际完成的频道记录，未做的频道后续仍能生成候选。

首版每个step对应一个候选宏动作，包括其中规定的自动安全处理，不把整个episode打包成一步。终局后禁止继续step。任务本身失败返回terminated并带reason；外部人为TimeLimit截断返回truncated并保留最终观测；rollout采满不是环境失败，也不自动reset。

对掩码之外但位于Discrete范围内的索引，提供显式invalid_action终止结果和负反馈，不执行替代物理动作，方便环境检查器诊断；训练和推理若出现该情况视为接口缺陷。范围外索引抛出明确输入异常。环境检查器通过并不代表完成正确，另测全套动作掩码和账本。

验收：757个数全有限；按相同公开历史更换不可见真值不会改变输入和掩码；NEAR插入清除也正确计费；随机合法策略能回放；实际动作ID与采样索引始终对应；所有渠道排除成本计入episode。

## Step C4：先交付仿真回放与回测底座

训练前先让随机合法策略和规则B运行同一环境，保存事件JSONL。回放图显示机器人路径、检测点、频道、当时可行域、清除时刻、虚拟时间和结束原因；真值展示仅在评估回放模式开放，绝不回流策略。支持输出轨迹PNG与时间分解图；逐步回放可独立运行，训练过程默认不渲染、不逐步打印。

每局记录：scenario_id、配置与代码哈希、策略/模型ID、目标数、真实清除频道集合、公开完成证据、结束原因、清除比例、总虚拟时间、总时间/清除数、wall_time、移动距离、检测/换频/清除次数、候选生成/几何/网络耗时、强制单选比例、兜底步数及耗时比例。清除数0的平均定位清除时间记NA。

旧统计中的中位数使用排序后的单个中间元素，偶数样本时应改成两个中间数均值；新评估器使用明确的标准中位数与固定分位数计算规则。旧输出不覆盖。异常局保留已经发生的事件，不能一次崩溃丢掉整批数据。

验收：手工动作总时间与日志分项和一致；B通过Gym外壳与直接公共会话执行同动作轨迹时结果一致；回放末状态与逐局CSV一致；CLI从代码根目录运行，输出位置不依赖任意工作目录。

## Step C5：轻量PPO短训练

使用MaskablePPO的MlpPolicy：Actor与Critic分别两层128单元、Tanh；输出分别为12个动作logits和1个价值估计。用框架已有策略头，不先写自定义PPO、CNN、LSTM或Transformer。

首版奖励为`-delta_virtual_s / 100`，首次发现与清除奖励均为0，正常完成终局额外奖励0。开发任务上限如500步若作为任务失败必须明确定义为failure并处罚，不能由早失败获得比完成更好的收益。故障失败处罚可先采用负3610的标度（100小时成本为3600），作为覆盖本地任务成本的保守起点；该大数可能影响价值训练，先诊断再通过验证集调整，不承诺大罚值保证成功。人为外部截断不套用该失败罚值。需要事件塑形时另开配置和消融，不在训练中无记录改奖励。

初始参数：learning_rate=3e-4，n_steps=1024，batch_size=128，n_epochs=5，gamma=1.0，gae_lambda=0.95，clip_range=0.2，ent_coef=0.01，vf_coef=0.5，max_grad_norm=0.5，target_kl=0.02，device=cpu。均为待验证起点。有限回合gamma=1贴近总时间成本，但GAE、函数逼近和PPO仍有近似，不能宣称严格最优。

先用单环境完成1万—5万步冒烟训练：保存、加载、确定性推理一致；加载后可继续训练。记录实际采样吞吐与优化耗时，再决定是否多进程。Windows多进程入口要受main保护，action_masks写在环境内，不用无法跨进程的外部掩码包装。CPU/GPU由实测速率决定。

每轮PPO使用当前策略的新rollout；历史所有轨迹不任意反复混用。若之后增加B专家行为克隆，独立采集同schema、同候选版本的状态动作对，作为另一个阶段做消融。

验收：没有NaN/无效采样；保存加载后动作一致；记录reward、value loss、KL、entropy及实际任务指标；不能只因loss下降就宣布有效。预训练检查点叫smoke，不标best或正式模型。

## Step C6：多种子训练与验证选模

已看过的0—29、1000—1099、2000—2001、3000—3099只作开发参考，不再称最终留出集。实施时核验现有输出再冻结场景清单。计划训练base_seed为10000—99999、验证100000—100099、留出200000—200099，每个清单配置相同的布局/误差组合；模型初始化种子用独立命名空间的11/22/33。

base_seed的所有布局、误差尺度和目标数变体归于同一数据分组，不跨训练/验证/留出。目标数覆盖10—16并单列10/13/16统计；误差场包含常量与空间变化，压力集包含边缘＋1000 m半径＋变化误差的组合。先用5类×100场景的验证预算，组合分布漂移集额外列出，不能把大量相关变体当独立证据。

三个模型种子同预算训练；在固定验证清单上按完成率优先、失败原因、配对成功时间与尾部耗时选模。建议每2万环境交互步评估一次；先10万步，再按验证表现与实际时间决定是否扩到30万/100万步。预先设置总训练时间上限和连续5次评估无改进的停止规则，不承诺固定步数收敛。

验证仍用maskable评估流程。普通MaskableEvalCallback主要按回报选模型，需在callbacks中额外实现任务指标优先的选模记录。归一化使用固定尺度；如后来启用VecNormalize，统计量随模型保存且评估时冻结。

## Step C7：冻结后做独立配对回测与消融

主对照是同候选v2、同公共执行器和同安全规则的B与C。旧固定七点策略作为完整系统参考；它的动作组织不同，不能把它与C的差异全部归因于神经网络。

最终测试前冻结代码、依赖、候选、特征、奖励和模型。每场景分别独立初始化相同真值，运行固定/B/C。报告全清率、公开证据完成率、清除比例、失败原因、平均定位清除时间、总虚拟时间P50/P95/最大值和实际推理耗时。时间配对只在共同成功子集计算，并同时完整报告失败数及其成本。

输出每类布局/误差的均值和配对差值，均衡五类汇总只是测试集权重，不能当作官方场景分布期望。置信区间按base_seed成组bootstrap，同一seed多个profile作为一组重采样；不同模型种子分开展示，不把所有重复当独立样本。100%实测只说明未观察到失败。

优先消融：人工评分替换PPO；去掉可行域位置/大小特征；事件奖励开关；改变强制接管条件仅作本地诊断。监测PPO是否主要依赖兜底完成。消融先用开发/验证清单；预先登记后才能用最终集作一次结果展示。看过最终结果后若继续调参，要重新指定未使用测试清单。

交付：配对episodes.csv、aggregate.json、report.md、分布和误差分组表、时间分解图、成功与失败轨迹、每模型的训练配置。判断是否采用C以可靠性、收益和耗时共同决定，没有必须超过某个任意百分比的统一门槛。

## Step C8：推理交付和官方接口演练

模型包保存model.zip、schema.json、config.json、候选版本、依赖锁定、训练/验证清单哈希和验证摘要。run显式加载模型并校验版本；推理传当前action_masks。模型缺失或schema不匹配时在决策前切换B，记录实际策略；不声称该局由C完成。

官方后端接入同一EpisodeSession，但必须按附件确认字段、计费、会话和超时语义。可以先完成本地C，再做接口演练；然而B和C都通过相同后端的基本回归，不能因为保留了B代码就认为B自动具备官方回退能力。本地wall_time没有网络等待，不能推断正式任务20分钟预算已满足。

## 3. 分阶段交付与下一步

第一个交付物是C0—C4：可运行的二维仿真环境、真实可行域、随机/规则动作驱动、轨迹回放和可信回测。此时仍没有训练好的PPO。

第二个交付物是C5：小型PPO训练闭环、可保存加载的冒烟模型与诊断日志。

第三个交付物是C6—C7：多训练种子、验证选模和独立回测，才有资格讨论C是否优于B。

第四个交付物是C8：冻结推理包与官方演练验证。

实际下一步执行C0：保存B参考快照，定义公共会话、结束原因和计时契约；然后C1补几何与误差场。不能先把现有B的choose包进PPO，再把其规则选择解释为网络决策。

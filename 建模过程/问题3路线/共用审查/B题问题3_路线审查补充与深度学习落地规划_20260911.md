## Step 1：结论与需要补强的地方

当前采用统一安全控制框架：B的固定扫描和主动评分作为规则基线与回退，C的混合场景PPO作为候选动作调度器。当前版本已经处理有界误差、空间区域摘要、固定地点误差、频道排除证据、清除计时、动作掩码和本地回测；仍不能据此宣称完成官方测试或在所有真实场景优于规则策略。

最需要补强的是连续局部定位。现有select_second_detection_point只针对第一、第二次观测；worst_case_diameter也只把两个检测点传给几何求解器。不能直接反复调用它来代表已经利用全部历史。第三次以后应输入累计可行域、全部观测和当前位置。粒子接收覆盖率为1也只说明采样粒子被覆盖，不是连续区域的证明。

计算代价也需重做预算。现有默认41×25=1025个粒子、20个精修候选、5个误差点，单次选点最多产生102500次双测点区域求解，尚不含初筛。此为代码循环计数，不是耗时实测。应把旧函数作为参考或离线对照，在线训练采用低成本代理、缓存和少数候选精修。给神经网络配GPU不能自动加速这些Python几何循环。

12个候选是动作限制，网络无法选出列表之外的好动作。B/C比较必须记录候选配额、截断和频道轮转；至少比较K=12与较宽候选配置的规则策略，判断瓶颈是否来自候选生成。此扩展在首版闭环后做，不先扩大网络。

## Step 2：新增一个有明确进展保证的局部兜底

### 2.1 条件

适用本题问题3的静止全向源、全局角误差不超过1°、接收半径至少1000 m、直线精确移动和目标不移动的模型。机器人允许离开目标分布圆域；不能额外投影移动点回1800 m圆内，否则下面的证明不再原样成立。实际协议与浮点误差在实现时另加保守裕量。

### 2.2 递推及证明

当前位置为S，正常示向度为theta，目标G到S的有效距离上界为L。首次收到正常信号可取L=1500 m。令u(theta)为示向度单位向量，移动到

    S_new = S + (L/2) * u(theta).

真实距离r属于[0,L]，真实方向与theta的夹角delta满足|delta|≤1°，于是

    ||G-S_new||² = r² + L²/4 - rL cos(delta)
                  ≤ r² + L²/4 - rL cos(1°).

右侧关于r是凸函数，区间最大值在0或L。故

    ||G-S_new|| ≤ rho L,
    rho = sqrt(5/4-cos(1°)) ≈ 0.5001522817.

更新L_new=rho L。首次移动后L_new≤750.229 m，因此新点必在该源的接收半径内。若收到NEAR就原地清除；否则再次检测取得新示向度并重复。递推只用误差界，不用不同测点误差独立这一假设，也不要求误差均值为零。

从1500 m开始，连续移动后的距离上界为：750.228、375.228、187.671、93.864、46.946、23.480、11.744 m。因此最多7次移动进入20 m清除范围，第7次移动后可直接执行光学定位与清除，不必再测示向度。若此前可行域已经允许更早清除，则立即使用更好的证据。

在不插入其他任务、保持同频道、没有通信或操作失败的理想规则下，从第一次示向度获得之后计算，7次移动总距离约1488.710 m，6次追加检测加清除的虚拟耗时上界约332.742 s。该数是公式算出的保守上界，不是平均表现，也不是实际程序运行耗时。

### 2.3 与公共状态的结合

每次移动得出的距离球也是一条有效推导约束，应交给公共几何层，不能只在局部策略里保存却让清除掩码不知道它。外包多边形近似仍须保守。最简实现也可直接保存“当前点距离上界”作为独立清除证据；L加数值裕量≤20时允许清除。

如果中途调度到别处，旧上界只适用于旧位置，不能照搬到新位置。按三角不等式转移上界，或重新由完整区域求新位置覆盖半径。首版在强制局部兜底期间连续处理当前频道，避免不必要的证明和状态复杂性。

它提供有限步定位基线，不宣称时间最优或文献原创。七点覆盖、逐频道有限扫描、发现后此局部策略，可组成理想物理模型下的有限动作完成策略；HTTP延迟、故障和20分钟实际窗口仍需实测。

## Step 4：深度学习究竟学习什么

C学习“下一步选择哪个位置、哪些频道、哪种操作”，不是监督学习目标坐标，也不是训练机器人步态。训练数据由本地数值模拟器与当前策略交互产生，不需要下载图像数据集或预训练大模型。

保留路线C的757维：全局25、20频道各18、12候选各31。Actor与Critic各使用两层128单元的MLP作为首版建议，激活函数Tanh；Actor最终输出12个动作分数，Critic输出1个剩余回报估计。Critic不是清除数量预测器，也不需要另行采集人工标签。

掩码为真的槽位参与概率归一化，无效候选不能被选取。episode完成时先结束，不制造全部无效的下一次决策。训练、验证、部署必须共用features.py以及候选的排序、补零与截断规则。观测形成后缓存列表，step只能执行缓存中对应的动作，不能重新生成一次列表。

先用展平MLP验证是否存在学习收益。如果泛化不足，再试共享候选编码器：对每个候选特征与全局上下文使用同一评分网络，可减少对动作槽位的依赖。此方案需要定制策略，不是简单修改隐藏层大小。首版不加CNN、Transformer或LSTM；当前官方MaskablePPO文档明确不支持循环策略，不能把LSTM当作可直接打开的选项。

## Step 5：奖励和训练参数

先用可核账的时间成本

    reward = -delta_virtual_seconds / 100.

首次发现、首次清除奖励起初设0，先验收环境和总时间对账；如果学习信号确实不足，再分别开启事件奖励并做消融。正常完成终局奖励可为0。超预算等任务失败单独处罚，具体尺度依据训练场景成本量级在验证集确定，不能声称某个大罚值带来必胜保证。

固定目标数且都正常成功时，每个目标一次的事件奖励总量是常数；但失败路径、折扣和不同目标数混合下会影响学习。因此不能只看奖励曲线变好，要直接看全清率和任务时间。

首版建议参数仅为待调起点：

| 参数 | 起点 | 用途 |
|---|---:|---|
| device | cpu | 小型MLP先检查环境吞吐 |
| learning_rate | 3e-4 | 参数更新幅度 |
| n_steps | 1024 | 每个环境每轮收集的宏动作步数 |
| batch_size | 128 | 训练小批次；需整除实际rollout规模 |
| n_epochs | 5 | 同一轮新轨迹用于优化的轮数 |
| gamma | 1.0 | 有限回合总时间成本的起点；与0.999作敏感性比较 |
| gae_lambda | 0.95 | 优势估计的偏差方差折中 |
| clip_range | 0.2 | PPO概率比截断 |
| ent_coef | 0.01 | 初期探索；后续按验证表现调整 |
| vf_coef | 0.5 | 价值损失权重 |
| max_grad_norm | 0.5 | 梯度裁剪 |
| target_kl | 0.02 | 过大更新的提前停止参考值 |

gamma=1不意味着求得全局最优，也不消除GAE近似或训练方差。若使用时间折扣，要同步修改回报与优势估计；首版不自定义这一套。

PPO收集当前策略的新轨迹，计算回报与优势，再优化若干轮后收集新轨迹。rollout收满但episode未结束，不应强制reset；训练采样边界也不应直接判成任务失败。Gymnasium的terminated与truncated要区分，价值引导与最终观测交给兼容框架正确处理。

局部收缩测试至少覆盖真实误差为±1°、距离接近5/20/1500 m、359°跨零、目标在圆边缘、定位被打断后恢复。采样测试用于检查实现，不能代替上述连续变量证明。浮点实现应为移动上界与清除判据加入数值余量。

训练先用单环境定位错误。测量1000次有效交互的总耗时，再估计更大训练量；网络更新、评估和日志额外计时。是否增加多进程取决于测得的吞吐，不能仅按CPU核数拉满。小目标课程只用于诊断/热身，其最少目标数和结束检查必须显式配置；正式环境恢复10—16个，不能放松正式完成证据。

## Step 7：怎样判断PPO是否值得保留

至少比较固定覆盖加局部收缩、主动B、PPO-C，使用相同场景和底层执行规则。候选相同的B/C是调度收益的主要对照；改变候选集的实验另列。先看全清率与异常原因，再比较两者都成功的同一批场景上的时间差，并同时保留全部失败统计，避免只比较各自成功样本。

先准备50—100个验证场景作开发诊断，留出另一个固定测试清单；计算允许时扩大。建议至少3个训练种子，不能用最幸运的一次作为稳定结论。配置、场景与误差场种子、模型文件和特征schema一起保存。

必须额外记录：有效动作数量、只有一个有效动作的比例、兜底步数与时间比例、各类动作的选择频率、移动/检测/换频成本分解、全局排除耗时、网络推理与几何耗时。只有一个合法动作时，Actor在该状态没有动作选择空间；大量此类步骤会让“高成功率”更多反映公共兜底，而非学到了更好调度。

训练曲线记录reward、episode长度、KL、entropy和value loss作为诊断，但选模以实际任务指标为准。验证没有明确收益时使用固定扫描或主动评分作为部署决策器；验证有收益时使用PPO主策略并保留固定扫描回退。可选行为克隆需要先冻结候选规则并采集规则决策器的状态动作对；它是另一个训练阶段，不把旧轨迹直接混入PPO更新。

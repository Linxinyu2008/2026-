# B题问题3统一建模与代码流程

> 版本：2026-09-11。本文根据当前 `B题问_代码` 的实际结构整理，是问题3的主建模过程。原“路线B”和“路线C”文档保留为数学推导与实验记录，不再表示两套互斥的最终方案。

## 1. 总体思路

问题3不再拆成两条相互独立的路线，而是采用一套统一的“安全执行框架”，在同一套公开状态、候选动作、计时规则和回测平台上接入不同的决策器：

```text
官方模拟器或本地仿真器
          ↓
公共通信/执行层
          ↓
20频道公开状态 + 空间置信区域 + 七点排除证据
          ↓
固定候选动作列表（12个槽位）
          ↓
决策层
   ┌───────────────┬────────────────┬─────────────────┐
   │ 固定扫描基线   │ 主动评分决策器  │ 混合场景 PPO     │
   │ 最安全回退     │ 规则调度器      │ 主策略调度器     │
   └───────────────┴────────────────┴─────────────────┘
          ↓
安全校验、动作掩码、局部定位与清除
          ↓
任务完成、超时或异常报告
```

其中，固定扫描不是被放弃的旧路线，主动评分也不是与 PPO 竞争的另一套物理模型。它们都是同一个执行框架下的决策层：固定扫描用于基线和最终回退，主动评分用于规则对照，PPO用于学习候选动作的调度顺序。

## 2. 统一的状态和物理规则

目标区域为圆心 `(0,0)`、半径 `1800 m` 的圆形区域；干扰源数量为 `10—16`，频道属于 `1—20` 且互不重复。机器狗从 `(0,0)`、测向机频道 `1` 开始。

统一执行规则为：

- 移动耗时为直线距离除以 `5 m/s`；
- `/measure` 每个频道耗时 `5 s`；
- 两次相邻检测频道不同，增加 `1 s` 换频时间；
- `/clear` 的频道只指定待清除目标，不改变测向机频道；
- `/clear` 成功耗时 `5 s`，未发现目标耗时 `3 s`；
- 距离目标不超过 `5 m` 时返回近距离信息；
- 距离目标不超过 `20 m` 时可以清除；
- 示向误差使用题目给出的 `±1°` 有界误差；
- 本地仿真固定同一地点的误差，不能通过重复检测制造独立误差样本。

代码对应公共层：

```text
B题问_代码/q3_common/public/
├── models.py          动作、测量、清除结果和机器人状态
├── config.py          题目规则和算法参数
├── scenario.py        可复现场景与固定误差场
├── simulator.py       本地移动、检测、清除和虚拟计时
├── official_client.py 官方HTTP接口客户端
├── geometry.py        多次示向观测的角域置信区域
├── coverage.py        20频道状态和七点排除证据
└── candidates.py      稳定的12槽候选动作
```

策略层只能看到公开状态，不能读取本地场景中的目标真值。真值只允许由仿真器和评估器使用。

## 3. 空间置信区域与频道状态

每个频道维护五种状态：

```text
UNKNOWN → TRACKING → CLEARABLE → CLEARED
                     └──────────→ ABSENT
```

`BEARING` 观测会把当前频道的历史观测转换为多个 ±1° 角域半平面，并计算空间置信区域的：

- 区域状态；
- 区域中心；
- 外包半径；
- 区域面积；
- 区域顶点。

`NEAR` 观测直接产生清除机会。`NONE` 观测只在对应七点覆盖证据中记录，不能单独把频道判定为不存在。七个覆盖点都确认无信号后，频道才可以进入 `ABSENT`。

当置信区域外包半径满足清除条件时，候选层可以生成 `CLEAR` 动作；PPO只负责选择动作，不负责替代几何清除保证。

## 4. 统一候选动作

每一步都生成固定12个候选槽位：

```text
4个 SCAN
4个 LOCALIZE
3个 CLEAR
1个兜底动作
```

候选动作包含：动作类型、位置、频道集合、预计耗时、搜索收益、定位收益、是否保证清除和是否有效。候选生成、排序、补零和动作掩码在训练、回测和部署时必须完全一致。

三种决策层都只能从这12个候选中选择：

### 4.1 固定扫描基线

优先选择当前待完成的 `SCAN`，没有扫描候选时选择第一个合法动作。它的作用是：

- 提供最简单的可解释基线；
- 验证公共执行器和完成条件；
- 在 PPO 模型缺失或异常时保证程序继续运行。

### 4.2 主动评分决策器

对候选动作计算：


\[
J(a)=\frac{w_s G_s(a)+w_l G_l(a)+w_c I_{\mathrm{clear}}(a)}{1+T(a)/T_0},
\]

选择评分最大的合法动作。它是规则对照策略，不是独立物理模型。

### 4.3 混合场景 PPO

PPO输入统一的757维公开特征：

- 全局特征25维；
- 20个频道，每个18维；
- 12个候选动作，每个31维。

PPO输出12个动作分数，动作掩码保证无效候选不参与选择。PPO只学习“下一步选哪个候选动作”，不预测目标真实坐标，也不替代公共执行器的移动、检测和清除规则。

训练场景混合使用 `uniform`、`edge`、`clustered`、`min_radius` 和 `max_error`，避免模型只适应一种目标布局。

奖励采用可核账形式：

\[
r_t=-\frac{\Delta T_t}{T_0}
+\lambda_f\Delta N_{\mathrm{found}}
+\lambda_c\Delta N_{\mathrm{cleared}}
-\lambda_r I_{\mathrm{repeat\ scan}}.
\]

## 5. 安全控制与回退

统一控制器采用以下优先级：

```text
加载 PPO 模型
    ↓成功
PPO 根据动作掩码选择候选
    ↓失败、非法动作、掩码异常或模型缺失
固定扫描/规则动作回退
    ↓
公共执行器执行
```

回退时记录：

- 请求模式；
- 实际执行模式；
- 是否发生回退；
- 回退原因；
- 已执行动作数；
- 虚拟时间；
- 清除数量；
- 结束原因。

因此，PPO模型异常不会直接导致整局程序崩溃。

## 6. 本地回测和正式接口

本地回测统一比较：

- 随机合法动作；
- 固定扫描；
- 主动评分；
- 混合场景 PPO。

每个策略使用相同场景种子、目标数量和公共执行规则，记录清除率、虚拟时间、决策步数、检测次数和频道切换次数。

正式平台则由 `official_client.py` 和 `official_controller.py` 承担：

```text
/enter
→ /measure
→ 更新公开状态和置信区域
→ 选择候选动作
→ /measure 或 /clear
→ 完成后 /exit
```

官方客户端负责 `robot_id`、`arena_id`、`request_id`、`accepted` 响应、同请求重试和现实时间预算。正式三次测试的结果必须来自官方模拟器，不能用本地回测结果替代。

## 7. 最终方案表述

问题3的最终方案不再写成“路线B和路线C二选一”，而应写成：

> 本文建立统一的有界误差搜索与清除框架。框架以公共几何状态、七点排除证据、候选动作生成和安全执行器为基础；固定扫描提供可解释基线和故障回退，主动评分提供规则调度基线，混合场景 PPO 在相同候选动作和执行规则上学习搜索、定位与清除动作的调度顺序。最终部署采用 PPO 主策略与固定扫描安全回退的串联控制结构。

这样写能够同时解释：

- 为什么需要固定扫描；
- 为什么要保留主动评分；
- PPO究竟学习什么；
- 三种策略为什么可以公平比较；
- 模型异常时如何保证程序仍然可运行。

## 8. 当前完成边界

当前代码已经完成统一状态、候选、执行、PPO、回测和回退结构，并新增官方客户端与官方控制器。空间区域目前主要使用正向 `BEARING` 半平面约束；定向覆盖角的非凸排除区域和正式平台三次测试仍需在官方模拟器上验证，不能在建模正文中提前写成已完成事实。
